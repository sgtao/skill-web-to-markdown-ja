# 添付・手元のファイル

対象: html・pdf・docx・xlsx・pptx。URL の取得はしない（できない環境でも使える）。

## A. スクリプトを実行できるとき

```bash
<RUN> <SKILL_DIR>/scripts/fetch_convert.py --help
```

読んだうえで、`--file <ファイルのパス>` を渡して変換する。経路の選び方と結果の見方は
`workflows/url.md` の「2. 変換する」「3. 結果の見方」と同じ。

- 添付は、まず作業用のフォルダに保存してからそのパスを渡す。
- 形式は中身で確かめられる（拡張子が違っていてもよい）。
- `ROUTE=direct` の docx / xlsx / pptx は `workflows/office-direct.md` も読む。
- 終わったら `workflows/finish.md` へ。

## B. Claude が直接読む（スクリプトを実行できないとき）

Claude.ai でコード実行が使えないときなど。**変換を始める前に、次を伝える。**

```
この環境ではスクリプトを実行できないため、添付を私が直接読んで Markdown にします。
- 図・グラフは再現しません（文章と表のみ。図があった位置に注記を残します）。
- 画像は取り出せません。
- 長い文書では、取りこぼしが出ることがあります。
```

進め方:
1. 添付を読み、見出し構造・本文・表を Markdown に写す。表は Markdown の表にする。
2. 図・グラフ・画像の位置には `> [図: <何の図か>。この変換では再現していません]` と書く。
3. 読めなかった部分・自信のない部分は、末尾の「この変換で再現できなかったもの」に箇条書きにする。
4. フロントマターは `workflows/finish.md` の項目を**手で書く**。`conversion: model-read`、
   `has_figures: false`。`retrieved_at` は現在の日時。
5. 返答の最後に、再現しなかったものを一言で繰り返す。

URL を渡されたが、取得できない環境のときは、ここへは進まず
SKILL.md の「失敗したとき」の形で `NO_NETWORK` として返す（ファイルとして渡してもらう）。
